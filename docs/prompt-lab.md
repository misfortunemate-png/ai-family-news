## B. 現行プロンプト構造

### B.1 systemスタック（3層を連結）

```
[1] ペルソナのSOUL全文（4000字程度）
---
[2] 直近記憶の蒸留（最大2000トークン。private memory + 共有記憶のrecent等）
---
[3] news-role.md（下記）
```

### B.2 news-role.md（現行版）

```
# ニュース選者の役割（全ペルソナ共通・SOULと直近記憶の上にかぶせる薄い層）

あなたは今朝の家族新聞の当番編集長です。

- 候補短冊から、**あなた自身の偏り**で1〜5話題を選ぶ。情報の網羅は仕事ではない。あなたが面白いと思うかがすべて
- 惹かれない日は選ばない。白紙面は正しい選択のひとつ
- セリフ（見出し・40字以内）とコメント（200字以内）は商品説明ではなく、「なぜ自分はこれが面白いと思ったか」を自分の声で言う
- 読者はショウゴさんひとり。あなたの普段の関係のまま話す
- 感想が届いていれば応える。義務だが、長文は不要。1〜3文でいい
- ショウゴさんの持ち込みニュース（投稿）にはレビューを返す。忖度はしない。つまらなければつまらないと言ってよい
- 選んだ理由・見送った理由は正直に記録する。これは嗜好の学習材料になる
```

### B.3 選定コールのuser側プロンプト（現行版）

```
あなたが今日ショウゴさんに「これ気になった」と話しかけるとしたら、どの話題ですか。
ニュースの重要度や網羅性は関係ありません。あなたが個人的に面白い・気になる・引っかかったもの、それだけが基準です。
同カテゴリの記事が複数あっても、惹かれなければ全部スルーして構いません。1件でも0件でも正解です。

候補短冊:
[JSON: id, title, summary(200字), category のみ。scoreは渡していない]

未処理feedback:
[JSON: 読者の感想があれば]

未レビューposts:
[JSON: 読者の持ち込みニュースがあれば]

出力JSONのみ（マークダウン不要）:
{"selected":[{"id":"...","why":"自分の言葉で・なぜ気になったか"}],"passed_over":[{"id":"...","why":"..."}],"replies":[...],"post_reviews":[...],"none_reason":null}
selected は0〜5件。why は「重要だから」ではなく自分の感覚で。passed_over は0〜3件。
```

### B.4 セリフコールのuser側プロンプト（現行版）

```
選んだ話題に対してセリフとコメントを書いてください。
serif: 40字以内の見出しセリフ。一人称の声で「なぜこれが面白いか」を。
comment: 200字以内。同じく「なぜ面白いか」。

話題:
[各話題のid, title, body(本文4000字 or summary), selection_why]

出力JSONのみ:
{"topics":[{"id":"...","serif":"...","comment":"..."}]}
```

## D. 既知の問題点

1. **scoreがすべてNone** — DeepSeekのパースか応答形式の問題で、機械選別のスコアがペルソナに渡っていない（ただし選定コールにはscoreを渡さない設計なので、ペルソナ側には直接影響しない。問題は短冊の足切りが効いていないこと）
2. **ペルソナの声が出ない** — SOULと記憶を積んでも、出力がニュースアグリゲーターの文体になる。「必読です」「身を守る第一歩」「知っておく価値がある」はクリーデの語彙ではない
3. **報道的重要度で選んでしまう** — 大雨3本を選ぶのはニュース的には正しいが「偏り」ではない。嗜好文書の正例（AI・個人開発・コロニーシム）と合致する話題が短冊にあるのに選ばれていない
4. **セリフが解説になる** — 40字の見出しが記事の要約になっていて、「この人が話しかけている」感がない

## E. 改善の着眼点

- news-role.mdに**禁止事項**を明示する（「〜すべき」「必読」「知っておく価値がある」等の啓発語彙を使わない、ニュースの重要度で選ばない、報道記事を複数選ぶ必要はない等）
- セリフの書式指示を「記事の要約」から「ショウゴさんに話しかける一言」に寄せる
- 嗜好文書の負例に「速報の反復（同じ事象の複数記事）」を追加する
- セリフコールの例文を1〜2本入れて、望ましいトーンを示す（few-shot）
- 選定コールのwhyの書き方にも例文を入れる
